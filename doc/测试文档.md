# Loom · AI 页面工坊 测试文档

> 文档日期：2026-11-26  
> 适用代码：当前工作区 `d:\bishidemo`  
> 测试类型：本地功能、异常兜底、接口安全、浏览器交互、部署配置检查

## 1. 测试目标

验证以下链路是否可独立演示和验收：

1. 自然语言生成可交互单文件 HTML 和后端代码；
2. 后端语言识别，默认 Java；
3. 五阶段进度展示及完成后的自动收起；
4. 预览 / 源码切换；
5. 历史记录持久化、删除、ZIP 下载；
6. 赛马双风格并行、左右预览、择优入库；
7. 点选元素后按自然语言在线修改；
8. 无 Key、接口异常时的 Mock 兜底；
9. 沙箱隔离、CSRF、密钥不入库不入 Git；
10. 生成期间删除历史等并发操作。

## 2. 测试范围

### 覆盖

- 本地开发服务器（Windows / Git Bash）
- SQLite 本地测试库和 PostgreSQL 配置解析
- 真实 DeepSeek 可选测试
- Mock 生成和网络异常兜底
- 浏览器 UI 与 iframe 交互
- 历史记录 API
- 基础安全属性

### 不覆盖

- 生产级压力测试、并发容量测试
- 深度渗透测试
- 各种浏览器/设备兼容矩阵
- 大模型输出质量的稳定性评估
- 阿里云 ECS 实际部署验证
- 真实 PostgreSQL / RDS 连接验证（代码已支持，本地环境使用 SQLite 回退）
- 自动生成的第三方后端代码运行测试

## 4. 本地准备

### 4.1 安装依赖

```bash
cd /d/bishidemo

# 当前工作区已有 .venv，可直接激活
source .venv/Scripts/activate

# 如没有虚拟环境：
# py -m venv .venv
# source .venv/Scripts/activate
pip install -r requirements.txt
```

### 4.2 配置环境变量

本地 `.env` 已存在时可直接使用。新环境从模板复制：

```bash
cp .env.example .env
```

真实模型模式至少配置：

```env
DEBUG=True
SECRET_KEY=本地随机字符串
ALLOWED_HOSTS=localhost,127.0.0.1

LLM_API_KEY=你的DeepSeekKey
LLM_BASE_URL=https://api.deepseek.com
LLM_MODEL=deepseek-chat
```

> 不要把真实 `.env` 提交到 Git。项目已将其加入 `.gitignore`。

### 4.3 数据库迁移

```bash
python manage.py migrate
python manage.py showmigrations generator
```

期望：`generator.0001_initial` 为 `[X]`。

### 4.4 启动服务

本机 8000 端口目前可能被其他旧项目占用，建议使用 8010：

```bash
python manage.py runserver 127.0.0.1:8010
```

访问：

```text
http://127.0.0.1:8010/
```

### 4.5 可选：隔离测试数据库

如果要避免污染当前历史记录，可使用独立的 SQLite 文件（Git Bash）：

```bash
DATABASE_URL='sqlite:///test_ui.sqlite3' python manage.py migrate
DATABASE_URL='sqlite:///test_ui.sqlite3' LLM_API_KEY= python manage.py runserver 127.0.0.1:8010
```

测试结束后删除 `test_ui.sqlite3`。

## 6. 功能测试用例

### TC-01 普通模式真实生成

**前置条件**：`.env` 配置有效 DeepSeek Key，服务已启动。

**步骤**：

1. 输入：`做一个咖啡店点单页，包含饮品卡片、规格选择和购物车，后端用 Python`
2. 点击「生成界面」。
3. 观察进度：需求规划 → 生成中 → 测试 → 验收 → 完成。
4. 等待约 2 秒，确认进度栏自动收起。
5. 查看预览和源码。

**期望**：

- 生成成功，预览可交互；
- 源码标签显示 `HTML + Python`；
- 后端标签能看到 Python 后端代码；
- 新记录出现在右侧历史栏；
- 进度栏完成后淡出隐藏。

**实际结果建议填写**：通过 / 失败，模型响应时间：____ 秒。

---

### TC-02 普通模式不限制风格

**步骤**：

1. 不勾选赛马模式。
2. 输入：`做一个赛博朋克风格的个人主页，紫青霓虹、深色背景，后端用 Go`
3. 生成后查看 HTML/CSS。

**期望**：

- 页面风格由用户提示词决定，不应被固定为庄重内敛或活泼艳丽；
- 后端源码为 Go；
- 页面与源码均正常显示。

**验证要点**：检查源码中是否出现用户要求的配色/风格关键词，而不是模板固定风格。

### TC-04 预览 / 源码切换

**步骤**：

1. 生成任意页面。

**期望**：

### TC-05 iframe 沙箱与 localStorage 兼容

**步骤**：

1. 生成一个使用 `localStorage` 保存状态的页面，例如：`做一个番茄钟，25 分钟专注 + 5 分钟休息，完成次数按天保存`
2. 点击「开始」，等待 1–2 秒。
3. 打开浏览器开发者工具，检查 iframe 属性。

**期望**：

- iframe 只包含 `sandbox="allow-scripts"`，不含 `allow-same-origin`；
- 页面脚本不因 `localStorage` 抛出 `SecurityError`；
- 倒计时按钮、暂停、重置可正常操作。

**说明**：预览中的 localStorage 是内存 shim，刷新预览后数据重置；下载后的 HTML 使用真实浏览器 localStorage。

### TC-14 输入校验与 CSRF

**空输入**：

- 不输入内容点击生成，应出现前端提示，不发请求。

**CSRF**：

```bash
curl -i -X POST http://127.0.0.1:8010/api/generate/ \
  -H "Content-Type: application/json" \
  -d '{"prompt":"test","race_mode":false}'
```

**期望**：返回 403，不调用大模型。

**超长输入**：

- 输入超过 2000 字符时应被前端限制或后端返回 400。

## 9. 已知非缺陷限制

以下行为是当前设计边界，不建议误判为功能缺陷：

1. “测试 / 验收”是 UI 阶段，不是服务器真实自动测试。
2. 生成后端不会自动运行，前后端未联调。
3. 生成后端没有默认数据库；当前模型可能生成内存实现。
4. 预览 localStorage 为内存兼容层，刷新预览后数据重置。
5. 赛马候选在点击选择前仅保存在浏览器内，刷新会丢失。
6. 模型输出存在非确定性，同一提示词两次效果可能不同。
7. 代码仓库没有内置自动化测试套件，本文件描述的是人工回归流程。

## 10. 测试完成标准

同时满足以下条件可判定本地测试通过：

- TC-01 到 TC-16 中 P0/P1 项通过；
- Mock 模式不影响主链路；
- 刷新后历史记录不丢失；
- 生成中删除历史不阻塞；
- 预览沙箱属性正确；
- 无真实密钥进入源码或 Git；
- 测试记录中有明确的截图或操作结论。
